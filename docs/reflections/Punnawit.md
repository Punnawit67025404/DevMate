1: สะท้อนคิดเรื่อง "หน้าต่างที่แตก" (Broken Windows)
จากความเข้าใจจะให้ผลคล้ายกับ Butterfly Effect ที่เมื่อเราสร้างบางอย่างทับสิ่งที่พังจะทำให้ปัญหาที่เกิดขึ้นภายใหญ๋กว่าสิ่งที่ควรจะเป็นก่อนหน้า
    
    การเปรียบเปรย
        ถ้าสร้างบ้านแล้วมีเสานึงเอียงหากไม่แก้ปัญหาอาจจะเกิดปัญหาเล็กน้อยบ่อยๆและใหญ่ขึ้นเรื่อยๆจน
        โครงสร้างนั้นไม่สามารถรับไหวจนพังลงได้ท้ายที่สุด

    ผลกระทบระยะยาว:
        - ทีมหมดความมั่นใจในการแก้โค้ด (Refactor) เพราะไม่มีตัวเช็คความถูกต้อง
        - บั๊กหลุดไปถึงหน้างาน (Production) มากขึ้นเรื่อยๆ
        - สุดท้ายทีมต้องเสียเวลากว่าครึ่งหนึ่งในแต่ละสัปดาห์เพื่อตามแก้บั๊กรายวัน แทนที่จะได้พัฒนาฟีเจอร์ใหม่

 2: Take Responsibility
 Take Responsibility คือการรับผิบชอบต่อการกระทำของตนที่ทำให้เกิดปัญหาต่อผู้อื่นและหาทางแก้ไขโดยที่ไม่โทษหรือโยนความผิดให้
 คนอื่น

    การเปรียบเปรย
        หากงานในความรับผิดชอบของกลุ่มปัญหาแทนที่จะหาว่าใครเป็นคนทำผิด
        สู้เอาเวลามาช่วยกันหาทางแก้ดีกว่า(ถ้าหาทางแก้ช่วยกันอาจจะทำให้ปัญหาผ่านพ้นไปได้)

    ความเข้าใจโดยย่อ
        - กล้ายอมรับหากเกิดความผิด
        - ไม่หาผู้รับผิดหรือผู้รับโทษ แต่มาหากเหตุของปัญหาและวิธีแก้ไขแทน
    
    นำ Provide Options, Don't Make Lame Excuses มาใช้ตัวอย่างสถานการณ์
        - เอางานขึ้น github ผิดแล้วไม่โทษว่าเป็นความผิดพลาดของใครไม่ว่าจะด้วยความไม่รู้อะไรก็ตาม
        แต่เลือกที่จะช่วยกันแก้ปัญหาแทน (ตัวอย่างเกิดขึ้นจากความไม่คุ้นชินกับตัวระบบ)
