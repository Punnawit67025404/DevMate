Pragmatic Promise
    
    เมื่อผมพบปัญหาในการทำงาน หรือคาดว่าจะส่งงานไม่ทันตามกำหนดเวลา ผมจะไม่ใช้ข้อแก้ตัวใดๆ แต่จะแจ้งให้เพื่อนในทีมทราบล่วงหน้าทันที พร้อมเสนอทางเลือกในการแก้ไขปัญหาอย่างน้อย 2 ทางเสมอ เพื่อให้ทีมร่วมกันตัดสินใจได้อย่างมีประสิทธิภาพ

ทำไมอยากเรียน SE
    
    ผมต้องการยกระดับทักษะจากการเป็นเพียงผู้เขียนโปรแกรม (Coder) ไปสู่การเป็นวิศวกรซอฟต์แวร์ (Software Engineer) ที่เข้าใจกระบวนการออกแบบและพัฒนาอย่างเป็นระบบ นอกจากนี้ยังต้องการเรียนรู้วิธีการทำงานร่วมกันในทีมผ่าน Git Workflow และการรีวิวโค้ดอย่างมืออาชีพ เพื่อเตรียมความพร้อมสำหรับการทำงานจริงในอุตสาหกรรม

Broken Window ที่เคยเจอ

    Window คืออะไร: ในการทำโปรเจกต์วิชาโปรแกรมมิ่งภาคเรียนก่อน ผมเคยละเลยการจัดระเบียบไฟล์ ตั้งชื่อตัวแปรแบบชั่วคราว และปล่อยให้มีโค้ดส่วนเกินที่ไม่ได้ใช้งาน (Dead Code) รกอยู่ในไฟล์หลัก โดยคิดว่าจะกลับมาแก้ไขภายหลัง

    ผลกระทบ: เมื่อโปรเจกต์ขยายใหญ่ขึ้น โค้ดที่รกกลายเป็น Technical Debt ที่อ่านยาก เพื่อนในทีมสับสนและนำฟังก์ชันเก่าที่ยกเลิกไปแล้วกลับมาเรียกใช้จนเกิด Bug ร้ายแรง ส่งผลให้ทุกคนต้องเสียเวลาอดนอนเพื่อตามแก้ปัญหาข้ามคืนก่อนวันส่งงาน

    ถ้าแก้ทันทีจะป้องกันอะไร: หากผมจัดการรีแฟกเตอร์ (Refactor) โค้ดและลบส่วนที่ไม่จำเป็นออกทันทีที่พบความรกรุงรัง จะช่วยป้องกันการสะสมของ Technical Debt ช่วยให้เพื่อนในทีมทำงานต่อได้ง่ายขึ้น และป้องกันความผิดพลาดที่สร้างความเสียหายกะทันหันก่อนวันส่งงาน
