# ข้อมูลแนะนำตัว

## 2. Pragmatic Promise

เมื่อพบปัญหาในการทำงาน จะรีบแจ้งสมาชิกในทีมและช่วยกันหาวิธีแก้ไขโดยไม่ปล่อยปัญหาทิ้งไว้ นอกจากนี้จะรับผิดชอบงานที่ได้รับมอบหมายให้เสร็จตามเวลา และพยายามใช้ Git/GitHub ให้เป็นระบบมากขึ้น เช่น การแบ่ง commit ให้ชัดเจนและสื่อความหมาย

## 3. ทำไมอยากเรียน SE (Software Engineering)

ต้องการเรียนรู้วิธีการทำงานด้านซอฟต์แวร์แบบเป็นระบบ โดยเฉพาะการทำงานร่วมกับผู้อื่นให้ใกล้เคียงกับการทำงานจริงในบริษัท และต้องการนำความรู้ที่ได้ไปประยุกต์ใช้กับการทำโปรเจกต์จบในอนาคต เพื่อให้สามารถทำงานร่วมกับทีมและจัดการโปรเจกต์ได้ดีขึ้น

## 4. ประสบการณ์ Broken Window ที่เคยเจอ

* **Window คืออะไร:**
  เคยทำโปรเจกต์โดยไม่ได้ใช้ Git อย่างเป็นระบบ และการ commit โค้ดไม่ค่อยมีรูปแบบที่ชัดเจน บางครั้งมีการแก้โค้ดหลายอย่างแล้วค่อย commit รวมกัน ทำให้ไม่สามารถรู้ได้ชัดเจนว่าแต่ละ commit มีการแก้ไขอะไรบ้าง

* **ผลกระทบ:**
  เมื่อเกิดปัญหาหรือมีบั๊ก ทำให้ย้อนกลับไปดูการเปลี่ยนแปลงของโค้ดได้ยาก และถ้าทำงานร่วมกับเพื่อนก็อาจทำให้การตรวจสอบหรือแก้ไขโค้ดของแต่ละคนทำได้ยากขึ้น

* **ถ้าแก้ทันทีจะป้องกันอะไร:**
  หากเริ่มใช้ Git และจัดการ commit ให้เป็นระบบตั้งแต่แรก จะช่วยให้สามารถติดตามการเปลี่ยนแปลงของโค้ดได้ง่ายขึ้น ย้อนกลับไปยังเวอร์ชันก่อนหน้าได้ และช่วยให้สมาชิกในทีมทำงานร่วมกันได้สะดวกมากขึ้น
