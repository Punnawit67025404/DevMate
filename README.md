# DevMate 🚀
> **Theme:** Tools for Modern Learners  
> **Project Description:** แพลตฟอร์มจับคู่ทีมทำโปรเจกต์จากทักษะ

DevMate คือแพลตฟอร์มที่เข้ามาแก้ปัญหานักศึกษาหาเพื่อนร่วมทีมทำโปรเจกต์ไม่ได้ตามทักษะที่ต้องการ โดยระบบเปิดให้ผู้ใช้ลงทะเบียนระบุทักษะความสามารถ (Skills) และระดับความเชี่ยวชาญของตนเอง จากนั้นสามารถตั้งโพสต์โปรเจกต์เพื่อค้นหาเพื่อนร่วมทีม โดยระบบจะทำการจับคู่ (Match) ความต้องการของโปรเจกต์เข้ากับผู้ใช้ที่มีทักษะตรงกัน ทำให้การสร้างสรรค์โปรเจกต์เกิดขึ้นได้จริงและมีประสิทธิภาพมากขึ้น

## 🤝 ข้อตกลงการทำงานของทีม (Ways of Working)

### 1. ตารางการประชุม (Meeting Cadence)

| การประชุม | ความถี่ | ระยะเวลา | เป้าหมาย |
| :--- | :--- | :--- | :--- |
| **Sprint Planning** | สัปดาห์ละ 1 ครั้ง | 45-60 นาที | กำหนดเป้าหมายของสปรินต์ เลือกงานจาก Backlog (เช่น ระบบจับคู่, ระบบโพสต์) และแบ่งผู้รับผิดชอบ |
| **Daily Stand-up** | สัปดาห์ละ 3 ครั้ง | 10-15 นาที | อัปเดตความคืบหน้า โดยตอบว่า: เมื่อวานทำอะไร? วันนี้จะทำอะไร? และมีอะไรติดขัด (Blocker) หรือไม่? |
| **Mid-Sprint Check-in** | สัปดาห์ละ 1 ครั้ง | 20-30 นาที | ตรวจสอบความคืบหน้าระหว่างสปรินต์ ปรับขอบเขตงานหากจำเป็น และช่วยกันแก้ Blocker ตั้งแต่เนิ่น ๆ |
| **Sprint Review/Demo** | ท้ายสปรินต์ | 30-45 นาที | สาธิตฟีเจอร์ที่ทำเสร็จ (เช่น ลองโพสต์และ Match สกิลดู) รับ Feedback และยืนยันความพร้อม |
| **Retrospective** | ท้ายสปรินต์ | 30 นาที | พูดคุยว่าสิ่งใดทำได้ดี สิ่งใดควรปรับปรุง และเลือก 1-2 ข้อที่จะพัฒนาในสปรินต์ถัดไป |

### 2. กติกาการสื่อสาร (Communication Rules)
* **ช่องทางหลัก:** ใช้ Discord หรือ Instagram Chat ของทีม
* **การตอบกลับ:** สมาชิกควรตอบข้อความที่เกี่ยวข้องกับโปรเจกต์ภายใน 24 ชั่วโมง ในวันทำการ
* **เรื่องเร่งด่วน:** หากเป็นปัญหาคอขาดบาดตาย (Blocker) ให้ขึ้นต้นข้อความด้วย `[URGENT]` และ Tag สมาชิกที่เกี่ยวข้องโดยตรง
* **ความโปร่งใส:** คุยเรื่องงานในช่องทางสาธารณะของทีมเสมอ เพื่อให้ทุกคนเห็นบริบทตรงกัน
* **Direct Message (DM):** ใช้เฉพาะเรื่องส่วนตัว หรือประเด็นที่ละเอียดอ่อนเท่านั้น
* **Thread / Reply:** ใช้ Thread เพื่อคุยต่อยอดในประเด็นย่อย (เช่น บั๊กหน้า Login) เพื่อไม่ให้แชทหลักรก
* **การบันทึก:** การตัดสินใจสำคัญต้องนำไปสรุปไว้ใน `README.md`, Issue Tracker หรือ Board ของโปรเจกต์
* **การลาพัก:** หากไม่ว่างเกิน 1 วัน ให้แจ้งทีมล่วงหน้าเสมอ

### 3. Git Workflow
#### 🌿 Branching
* Branch `main` ต้องเสถียรและใช้งานได้เสมอ **ห้าม Push โค้ดตรงลง main เด็ดขาด**
* งานทุกชิ้นต้องทำบน Feature Branch ที่แยกจาก `main`
* ตั้งชื่อ Branch ตามรูปแบบนี้:
  * `feature/short-description` (เช่น `feature/skill-matching-algo`)
  * `fix/short-description` (เช่น `fix/project-post-error`)
  * `docs/short-description` (เช่น `docs/add-api-endpoints`)
  * `refactor/short-description` (เช่น `refactor/user-profile-component`)

#### 📝 Commits
* ข้อความสั้น กระชับ และ ขึ้นต้นด้วยคำกริยา (Verb) เสมอ
* *ตัวอย่าง:* `Add skill selection dropdown`, `Fix matching algorithm bug`, `Update Figma design link`

#### 🔄 Pull Requests (PR)
* โค้ดทุกส่วนต้องผ่าน Pull Request
* **รายละเอียดใน PR:** ต้องมีสรุปสั้น ๆ ว่าแก้/เพิ่มอะไร ถ้าเป็นเรื่องหน้าตา UI ให้แนบ Screenshot มาด้วย
* **กฎการ Merge:** ต้องมีสมาชิก อย่างน้อย 1 คน เข้ามา Review และ Approve ก่อน Merge เสมอ
* หาก PR เกี่ยวข้องกับระบบหลัก (เช่น Algorithm จับคู่) ต้องให้ทีมรันทดสอบในเครื่อง Local ก่อน Merge
* ลบ Feature Branch ทิ้งทันทีที่ Merge สำเร็จ

### 4. การตัดสินใจ (Decision Making)
* **เน้นฉันทามติ (Consensus):** พยายามพูดคุยหาข้อตกลงร่วมกันเป็นหลัก
* **งานย่อย:** ผู้รับผิดชอบตัดสินใจได้เองหลังรับฟัง Feedback
* **เมื่อมีความเห็นต่าง (Tech/Design):**
  1. กางตัวเลือกทั้งหมดออกมา
  2. คุยข้อดี-ข้อเสีย (เช่น ความเร็ว, UX, ความซับซ้อนของโค้ด)
  3. **การโหวต:** หากตกลงไม่ได้ ให้ใช้เสียงข้างมาก (Majority Vote)
  4. **เมื่อคะแนนเสมอ:** ผู้ถือรับผิดชอบหลักมีสิทธิ์ชี้ขาด (Tech Lead สำหรับโค้ด/ระบบ, Design Lead สำหรับ UI/UX)
* ตัดสินใจแล้ว ต้องเดินหน้าทำตามร่วมกัน

## 👥 Requirements & Personas

### Persona (ผู้ใช้หลัก)
* **กิตติภัทร์:** นิสิตปี 2 สายพัฒนาเว็บที่มีไอเดียอยากทำแอปคาร์แคร์/จัดการคิว แต่เขาถนัดเฉพาะ Frontend (Next.js, Tailwind CSS) และยังขาดเพื่อนร่วมทีมที่เก่งระบบ Database แน่นๆ (Supabase/PostgreSQL) และคนช่วยดีไซน์หน้าเว็บ (Figma)

### Key Scenario (สถานการณ์ใช้งาน)
1. **Onboarding:** กิตติภัทร์เข้ามาลงทะเบียนในระบบ เลือกใส่สกิลของตัวเองว่า `Next.js (Advanced)`, `Tailwind CSS (Advanced)`
2. **Project Creation:** จากนั้นเขาเปิดโพสต์สร้างโปรเจกต์ใหม่ชื่อ *"Smart Carwash App"* พร้อมใส่รายละเอียดและแท็กสกิลที่ต้องการตามหา คือ `Supabase (Intermediate)` และ `Figma (Beginner)`
3. **Matching & Invite:** เมื่อกดโพสต์ ระบบจะทำการเปรียบเทียบข้อมูล (Matching) แล้วแสดงรายชื่อเพื่อนนิสิตในรายวิชาที่มีสกิลตรงกับที่โปรเจกต์ขาด เพื่อให้กิตติภัทร์กดส่งคำเชิญทักทายไปชวนมาร่วมทีมได้ทันที
